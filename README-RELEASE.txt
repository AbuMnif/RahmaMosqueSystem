منظومة عَون الإدارية — الإصدار Awn-v1.1.5

إصلاحات هذا الإصدار:
- إصلاح طريقة حفظ السجلات التعليمية: عمليات الكتابة تتم عبر جلسة المستخدم الموثقة حتى تعمل auth.uid() وسياسات RLS ومشغلات الحماية وسجل التدقيق بهوية المستخدم الصحيحة.
- إضافة ملف SQL باسم supabase/learning-record-manager-policies.sql لإضافة سياسات الكتابة للمدير والمشرف على جداول السجلات التعليمية الخمسة. يجب تشغيله مرة واحدة في Supabase SQL Editor قبل استخدام حفظ السجلات كمدير أو مشرف.
- توحيد القيم المرسلة إلى قاعدة البيانات بالرموز الإنجليزية المعتمدة في قيود Supabase، مع إبقاء واجهة المستخدم باللغة العربية:
  - الحضور: present / absent / late / excused
  - نوع سجل الحفظ: new_memorization / revision
  - تقدير الإتقان: excellent / very_good / good / acceptable / needs_improvement
  - أيام التدريس: saturday إلى friday
- إضافة كشف تحضير جماعي: علامة ✓ للحاضر وترك الخانة فارغة للغائب، مع حفظ جميع الطلاب المسجلين في الحلقة والتاريخ المحدد.
- دعم حفظ كشف التحضير دون اتصال ومزامنته تلقائيًا عند عودة الإنترنت، مع معرف مستقل لكل عملية ومنع إعادة إدخال العملية نفسها.
- التحقق من تسجيل الطالب في الحلقة وفق تاريخ السجل، وليس وفق حالة التسجيل الحالية فقط.
- إضافة متوسط درجات الاختبارات، والطلاب الذين يحتاجون إلى متابعة، ومؤشرات تقدم الطلاب.
- تحسين تصدير Excel بأوراق منفصلة تشمل ملخصًا ومؤشرات كل طالب والطلاب والحضور والحفظ والمراجعة والاختبارات والنتائج والملاحظات وسجل التدقيق.
- إظهار الحالات والتقديرات باللغة العربية في الواجهة وملف Excel، مع تخزين القيم الإنجليزية فقط في قاعدة البيانات.
- ربط زر السجل التعليمي من صفحة الطلاب بالسجل مع تحديد الطالب تلقائيًا بدل التوجيه إلى مسار ملف غير موجود.
- تحسين تنسيق كشف التحضير والجداول والملخصات للشاشات الصغيرة والكبيرة.
- تحديث إصدار Service Worker لإبطال التخزين المؤقت القديم.

خطوات قاعدة البيانات:
1. افتح Supabase ثم SQL Editor.
2. افتح الملف supabase/learning-record-manager-policies.sql من هذا الإصدار.
3. شغّل محتواه مرة واحدة.
4. لا تنفذ أي DROP TABLE أو حذف بيانات؛ الملف يحدّث سياسات RLS فقط.

ملاحظات:
- المعلم يحتاج إلى تسجيل الدخول والاتصال بالإنترنت أول مرة لتنزيل بياناته.
- الصفحات التي يراد فتحها دون اتصال يجب زيارتها مرة واحدة أثناء الاتصال ليحفظ المتصفح نسخة الصفحة وملفاتها.
- لم تُنشأ جداول أو أعمدة جديدة ولم تُحذف بيانات Supabase.
- تم فحص صياغة ملفات JS/JSX وملفات API والتحقق من المسارات النسبية وتوازن أقواس CSS.
- لم يتوفر تثبيت اعتماديات المشروع في بيئة العمل، لذلك لم يتم تشغيل بناء Next.js كاملًا أو اختبار اتصال Supabase/Vercel الفعلي. يلزم مراجعة بناء Vercel واختبار الحفظ الفعلي بعد تطبيق SQL.
